# Shani

**A trading harness that learns how *you* trade.**

Journals every trade with the chart you were actually looking at, asks you why
while it's still fresh, distills the answer into a reusable setup, and hands it
back the next time the same thing sets up.

## The problem

Your trading journal records numbers. Entry, exit, size, P&L. Maybe a one-line
note you wrote three hours later that says "good setup, bad exit."

What it does not record is **why you took the trade** and **what you were
actually looking at** when you took it. So six months and four hundred trades
later, you have a spreadsheet that can tell you your win rate and nothing that
can tell you *which of the things you do actually works*.

The lesson never compounds. You relearn the same mistake every quarter.

## What Shani does

```
   Pine alert ──▶ Shani ──▶ "You've taken this setup 7 times.
   fires                     4W / 3L, avg +1.2R.
                             Every loss was before 10:00 ET."
                                    │
                             you decide, you click
                                    │
                                    ▼
                            paper fill + chart
                            screenshot captured
                                    │
                        ┌───────────┴───────────┐
                        │  "Why did you take    │
                        │   this one?"          │  ← 90 seconds after the fill,
                        └───────────┬───────────┘    while you still remember
                                    │
                                    ▼
                        setup card, versioned,
                        indexed, retrievable ──┐
                                               │
                        ┌──────────────────────┘
                        ▼
              next matching signal knows about it
```

The loop is borrowed from [Nous Research's Hermes agent](https://github.com/NousResearch/hermes-agent),
which turns completed work into reusable procedure. Shani narrows that to
exactly one domain: your trades.

## The three planes

Shani talks to TradingView three different ways, because no single route does
everything. They are independent — you can run Plane A alone.

| | What it is | Needs | Gives you |
|---|---|---|---|
| **A** | TradingView's public screener endpoints | Nothing | Quotes, screeners, multi-timeframe TA across CME/NYMEX/COMEX |
| **B** | Chrome DevTools Protocol into TradingView **Desktop** | Paid TV Desktop | The chart *you* are on — symbol, timeframe, your indicators, screenshots, Pine editor access |
| **C** | Pine alert → HMAC-verified webhook | A tunnel | Real-time signals from your own scripts |

**Plane B is the one that makes this project different.** It's the only way for
Shani to know what you were actually staring at when you pulled the trigger.
Everything else is a number; that's context.

And together they close a loop none of them can alone:

> journal a trade → extract the setup → **Shani writes the Pine script for it**
> → the alert fires → Shani proposes it back with your own stats attached

Full setup: **[docs/tradingview-setup.md](docs/tradingview-setup.md)**

## Quickstart

Requires **Python 3.11+** and **Node 20+**.

```bash
git clone https://github.com/akaki2027/shani.git
cd shani
uv sync
uv run shani init
```

`shani init` walks you through configuration. Nothing needs an API key to start
— the paper broker and journal work fully offline.

```bash
uv run shani doctor   # verify every plane, with actionable failures
uv run shani demo     # seed synthetic history so the portal isn't empty
uv run shani serve    # portal at http://127.0.0.1:8420
```

To use a real model for the interview and proposals:

```bash
uv sync --extra anthropic
export ANTHROPIC_API_KEY=sk-ant-...
```

Or point it at Ollama and keep everything on your machine — your trade journal
is your edge written down, and it never has to leave the box. Model provider is
one config line; see [docs/learning-loop.md](docs/learning-loop.md).

## Safety

Live trading is not merely guarded — while `allow_live: false` (the default),
live broker adapters **are never registered**, so the code path does not exist
at runtime.

- Auto-execution on paper, human confirmation on live. Always.
- Kill switch, max daily loss, max position size, order rate limit.
- Append-only audit log of every signal, proposal, gate decision, and order.
- News and sentiment text is fenced as untrusted data before it reaches a model
  that proposes trades.
- API binds `127.0.0.1`; the tunnel exposes only the webhook path.

Details: **[docs/safety.md](docs/safety.md)**

## What is not verified

Alpha software about money should be specific about what it has and hasn't
proven. From the development environment:

- **Plane B** is written against TradingView Desktop's internal page API. Error
  handling is tested; a live chart read is not. TradingView can change that API
  in any release — when they do, [`shani/market/tradingview_cdp.py`](shani/market/tradingview_cdp.py)
  is the only file that needs fixing, by design.
- **Plane C** has locally-tested HMAC verification, but no real inbound alert
  from TradingView's servers has been confirmed.
- **NinjaTrader** ships as a documented stub. No NT8 instance was available.
- **Live execution** is untested by construction.
- **The paper broker is optimistic.** It models slippage and commission. It does
  not model queue position, partial fills in thin books, or a genuine fast
  market. Paper results always flatter you.

## Contributing

Contributions welcome — see [CONTRIBUTING.md](CONTRIBUTING.md).

Two rules specific to this project:

1. **Never relax the dependency pins without reading the comment above them.**
   `tradingview-screener==3.0.0` is pinned because 3.2+ makes futures queries
   return zero rows *silently*. That is the worst class of bug: no error, no
   warning, just a screener that quietly stops working.
2. **Contract specs need an independent source.** If you add an instrument, add
   its row to `EXCHANGE_SPECS` in `tests/test_instruments.py` by reading the
   exchange spec sheet — not by running the code and pasting the output. A test
   that derives its expectation from the code under test verifies nothing.
